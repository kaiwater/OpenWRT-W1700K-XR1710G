# 2026-11-01 — XR1710G 2.4G / MLO 修复记录

## 现象

2.4G AP 启动失败：

```text
hostapd: Cannot enable mld_ap when IEEE 802.11be is disabled
hostapd: 1 errors found in configuration file '<inline>'
hostapd: hostapd.add_iface failed for phy phy0.0 ifname=phy0.0-ap0
```

- `/var/run/hostapd/` 没有 `phy0.0-ap0` socket
- `iwinfo phy0.0-ap0`：`Channel: 0`、`Tx-Power: 0 dBm`
- `ap-mld0` 只有 5G link，2.4G link 缺失

客户端 `4E:5D:25:EE:71:9E`：

- 关联在 `ap-mld0`
- uplink 2401.9 Mbps，downlink 24 Mbps、`last ack signal 0`
- ARP `FAILED`，ping 100% 丢包

## 原因

- `wireless.radio0.htmode='HE20'`，没有 802.11be
- `wireless.mlo0.device='radio0' 'radio1'`，MLO 把 2.4G 也包含进去
- MLO 的 `mld_ap` 要求 802.11be，2.4G HE20 不满足

## 修复

```sh
uci set wireless.radio0.htmode='EHT20'
uci commit wireless
wifi reload
```

结果：

- 2.4G：channel 6 (2.437 GHz)，EHT20，20 dBm
- `ap-mld0` 两个 link：
  - link 0：2.4G ch6 EHT20
  - link 1：5G ch36 EHT160
- `/var/run/hostapd/` 出现 `ap-mld0_link0`、`ap-mld0_link1`、`phy0.0-ap0`

## 客户端测试

- 强制 deauth 后重新关联，MLD 两个 link 正常
- 但该客户端仍然出现间歇性下行异常：
  - 刚关联时 tx 2401.9 Mbps，随后降到 24 Mbps
  - ARP 从 `REACHABLE` 变 `FAILED`
  - ping 仍 100% 丢失（也可能是客户端屏蔽 ICMP）
- 尝试过：
  - 只保留 5G link（`mlo0.device='radio1'`）：客户端仍有下行问题
  - 临时停止 usteer：断连减少，但下行问题仍在
- 结论：MLO/MLD 本身已经正确，问题更像是**这个客户端与 MT7996 MLO 的互操作问题**，不是 2.4G link 缺失导致的

## 当前配置

已恢复为预期 MLO 配置：

```text
wireless.radio0.htmode='EHT20'
wireless.mlo0.device='radio0' 'radio1'
usteer 正常运行
```

## 建议

- 先让这个客户端连接 **5G 普通 SSID `3000M8_`**，验证是否能正常上网
- 如果 `3000M8_` 正常，说明是该客户端的 MLO 问题，可让这个客户端专用非 MLO SSID，其他客户端继续用 `3000M8-MLO`
- 如果不需要 MLO，最稳的是禁用 `mlo0`，统一用普通 2.4G/5G SSID
- 如果后续 MLO 客户端仍有问题，可以再临时停 usteer 做对比

## 备份

- `/root/wireless.bak-20261101-1455`：HE20 + 两个 link
- `/root/wireless.bak-mlo-20261101-1500`：EHT20 + 两个 link

## 注意

Release 镜像本身不包含这份无线配置；它保留在设备上。新装设备如果要使用 MLO，需要把 2.4G 设为 `EHT20`。
