# 2026-11-01 — XR1710G 两套 UBI 布局确认

## 背景

镜像文件名 `openwrt-airoha-an7581-gemtek_xr1710g-ubi-squashfs-sysupgrade.itb` 带 `-ubi` 后缀。近期 XR1710G 出现了两套布局，担心本镜像实际是“系统从 `0x20000` 开始”的新布局，在 stock uboot + chainloader 上第一次写入正常、重启后变砖。

## 结论

本仓库（`pbodq2/OpenWRT-W1700K-XR1710G`）的 `gemtek_xr1710g-ubi` **不是** `0x20000` 布局。

`target/linux/airoha/dts/an7581-xr1710g-ubi.dts`：

```text
vendor          0x00000000 - 0x00600000   6 MB
chainloader     0x00600000 - 0x00700000   1 MB
ubi             0x00700000 - 0x1be00000   系统分区
reserved_bmt    0x1be00000 - NAND 末尾
```

`bootargs`：

```text
console=ttyS0,115200 earlycon ubi.block=0,fit root=/dev/fit0 rootwait
```

系统从 **0x700000** 开始，和当前 stock uboot + chainloader 的合法偏移一致。

## 混淆来源

`naoki66/ImmortalWrt-for-Gemtek-brightspeed` 里 `gemtek_xr1710g-ubi` 用的是另一套 DTS：

```text
bl2     0x00000000 - 0x00020000
ubi     0x00020000 - NAND 末尾
```

它是 bl2/fip 新 bootloader 布局，系统从 `0x20000` 开始。两个仓库的镜像文件名都带 `-ubi`，但布局不同，不能只看后缀。

`naoki66` 仓库里真正对应本仓库 0x700000 布局的是非 ubi 的 `gemtek_xr1710g`（DTS `an7581-xr1710g.dts`）。

## 仍然需要注意

- 本镜像的 `DEVICE_COMPAT_VERSION` 是 `2.0`，元数据里明确写着：

  ```text
  image 2.0, device 1.0
  Partition table has been changed ... A reinstall including corrected chainloader is needed.
  ```

- 0x700000 偏移对，但 chainloader 必须是本仓库 README 说的 **ubi2.0 chainloader**（fit 卷 + reserved BMT），不能是旧 stock chainloader。
- 如果 chainloader 是 naoki66 的 bl2/fip 新布局（0x20000），则本镜像不适用，应使用 naoki66 的 `gemtek_xr1710g-ubi` 构建。
- 刷机前建议确认：

  ```sh
  cat /proc/mtd
  dmesg | grep -i ubi
  ```

  确认 UBI 分区偏移是 `0x700000`，且 chainloader 为 ubi2.0 版本。
