# 2026-11-01 — XR1710G fw_env 大小修正（0x4000）

## 设备实测

SSH 到 `root@192.168.2.152`：

```text
# cat /etc/fw_env.config
/dev/ubi0_1 0x0 0x4000 0x1f000 1
/dev/ubi0_2 0x0 0x4000 0x1f000 1

# uci show ubootenv
ubootenv.@ubootenv[0].envsize='0x4000'
ubootenv.@ubootenv[1].envsize='0x4000'
```

UBI 卷：

```text
fit, ubootenv (ubi0_1), ubootenv2 (ubi0_2), factory, rootfs_data
```

## 问题

本仓库 `package/boot/uboot-tools/uboot-envtools/files/airoha_an7581` 对 `gemtek,xr1710g-ubi` 走通用函数：

```sh
ubootenv_add_ubi_default
```

它生成的是：

```text
/dev/ubi0_1 0x0 0x1f000 0x1f000 1
/dev/ubi0_2 0x0 0x1f000 0x1f000 1
```

`envsize` 是 `0x1f000`，与 XR1710G chainloader 的 `CONFIG_ENV_SIZE=0x4000` 不一致。

naoki66 仓库对该问题有明确注释：

```text
CONFIG_ENV_SIZE=0x4000 for its redundant UBI environment.
Using the generic 0x1f000 layout makes fw_setenv write an environment
whose CRC the U-Boot rejects, so bootcmd changes never take effect.
```

## 改动

`airoha_an7581` 增加 XR1710G 专用函数：

```sh
ubootenv_add_ubi_xr1710g() {
	. /lib/upgrade/nand.sh
	local envubi=$(nand_find_ubi ubi)
	local dev=/dev/$(nand_find_volume $envubi ubootenv)
	local dev2=/dev/$(nand_find_volume $envubi ubootenv2)
	ubootenv_add_uci_config "$dev" "0x0" "0x4000" "0x1f000" "1"
	ubootenv_add_uci_config "$dev2" "0x0" "0x4000" "0x1f000" "1"
}
```

并让以下 board 使用它：

```text
gemtek,xr1710g
gemtek,xr1710g-ubi
```

W1700K 和 Nokia 仍使用通用 `0x1f000`。

## 影响

- 这是用户空间 `fw_printenv/fw_setenv` 的配置，不影响内核/chainloader 启动，本身不会变砖
- 但 `fw_setenv` 用错 `envsize` 时，写出的环境 CRC 会被 U-Boot 拒绝，`bootcmd` 等修改不生效
- 干净安装（不保留配置）时会生成 `0x1f000`，需要重新构建修正
- 升级时如果保留 `/etc/config/ubootenv`（设备当前是 `0x4000`），配置本身会保留；但 `/etc/fw_env.config` 可能不会被 sysupgrade 备份，必要时手动重建

## 手动修正（使用已构建的旧镜像时）

```sh
cat > /etc/fw_env.config <<'EOF'
/dev/ubi0_1 0x0 0x4000 0x1f000 1
/dev/ubi0_2 0x0 0x4000 0x1f000 1
EOF
```

并确认：

```sh
uci set ubootenv.@ubootenv[0].envsize='0x4000'
uci set ubootenv.@ubootenv[1].envsize='0x4000'
uci commit ubootenv
```
