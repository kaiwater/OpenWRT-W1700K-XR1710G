# 2026-11-01 — XR1710G 实际刷机记录（OpenWrt SNAPSHOT r0-9f45f0a）

## 目标

把 run `41260491406`（`9f45f0a`）的镜像刷到 XR1710G，保留配置。

- 镜像：`openwrt-airoha-an7581-gemtek_xr1710g-ubi_0x700000-squashfs-sysupgrade.itb`
- SHA256：`d4755f2f65519b3d64a4005839817040885b0b830b627ce181996d167c428853`
- 刷机前系统：ImmortalWrt `20261016-b7f03c2c-da63f7d6`，board `gemtek,xr1710g`，compat 1.0
- 配置备份：`/Users/bob/Downloads/backup-20261101-1415.tar.gz`

## 第一次尝试（未写入）

从 SSH 执行：

```sh
ssh root@192.168.2.152 'sysupgrade -F /tmp/firmware.bin'
```

结果：

- 提示 `Image metadata not present`，`--force given - will update anyway`
- 提示 `Commencing upgrade. Closing all shell sessions.`
- 约 65 秒后设备重新上线，但仍是旧 ImmortalWrt
- `fit` 卷仍是 655 LEBs（79.3MiB），`rootfs_data` 仍存在
- 说明 `nand_upgrade_prepare_ubi` 在删除/重建卷之前就失败了，镜像没有写入

推测原因：SSH 会话的 cwd 在 `/root`（overlay），stage2 无法干净地卸载/删除 `rootfs_data`，`ubirmvol` 失败后 `fit` 也没有被重建。另一个差异是第一次镜像检查提示 metadata 不存在。

## 第二次尝试（成功）

### 1. 让 compat 检查通过

在旧系统上：

```sh
uci set system.@system[0].compat_version='2.0'
uci commit system
```

（`/lib/upgrade/fwtool.sh` 读取 `system.@system[0].compat_version`，未设置时默认 1.0。）

### 2. 从 `/tmp` 执行

```sh
scp openwrt-...-sysupgrade.itb root@192.168.2.152:/tmp/fw.itb
ssh root@192.168.2.152 'sha256sum /tmp/fw.itb'
# d4755f2f...  与 artifact 一致
ssh root@192.168.2.152 'cd /tmp && sysupgrade -F /tmp/fw.itb'
```

关键点：`cd /tmp` 后再执行，避免 SSH cwd 占住 overlay。

## 结果

约 115 秒后新系统上线：

- OpenWrt SNAPSHOT `r0-9f45f0a`
- board：`gemtek,xr1710g-ubi`
- compat：`2.0`
- `fit` 卷：694 LEBs = **88,121,344 bytes（84.0 MiB）**
- `rootfs_data` / overlay：300.6M，已用 8.5M
- 配置保留：hostname `XR1710G`，LAN `192.168.12.1/22`
- 已安装：
  - `luci-app-airoha-fancontrol`
  - `luci-app-passwall`
  - `xray-core`
  - `sing-box`
- `fw_env.config` 为 0x4000
- `fw_printenv` 曾提示 `Bad CRC`；执行 `fw_setenv bootdelay 2` 后写入有效 env，`fw_printenv bootdelay` 正常返回 `2`

## 经验

- SSH 升级一定要 `cd /tmp` 再执行 `sysupgrade`，不要从 `/root` 启动
- 1.0 -> 2.0 的 compat 检查可以：
  - 设置 `system.@system[0].compat_version='2.0'`，或
  - 直接用 `sysupgrade -F`
- 不需要用 chainloader 裸写镜像；`sysupgrade` 会重建 `fit` 卷到 84.0MiB 并缩小 `rootfs_data`
- 刷完后设备已经是 `gemtek,xr1710g-ubi` / compat 2.0，后续升级不再需要强制
- 旧 env 的 CRC 是坏的，chainloader 一直用默认 env；写入一次有效 env 即可修复
