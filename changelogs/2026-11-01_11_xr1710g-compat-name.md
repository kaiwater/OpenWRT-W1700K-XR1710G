# 2026-11-01 — XR1710G 兼容设备名与镜像文件名标注

## 背景

设备实际 board name 是 `gemtek,xr1710g`（naoki66 的非 ubi profile），而本仓库镜像是 `gemtek,xr1710g-ubi`。两者 DTS 的系统偏移都是 `0x700000`，但 `sysupgrade` 会因为 board name / compat version 不一致给出警告。

同时，XR1710G 存在两套完全不同的布局：

- 本仓库 `gemtek_xr1710g-ubi`：UBI 从 **0x700000** 开始（stock U-Boot + chainloader）
- naoki66 `gemtek_xr1710g-ubi`：bl2 0x0，UBI 从 **0x20000** 开始（bl2/fip 新 bootloader）

镜像文件名都带 `-ubi`，用户很难区分。

## 改动

### 1. 兼容设备名

`target/linux/airoha/image/an7581.mk`：

```make
SUPPORTED_DEVICES := gemtek,xr1710g gemtek,xr1710g-ubi
```

这样从当前 `gemtek,xr1710g` 系统升级时，不会再因为 board name 不匹配被拒绝。`DEVICE_COMPAT_VERSION` 仍是 `2.0`，compat 检查仍会提示；设备已经使用 ubi2.0 chainloader，必要时用 `-F`。

### 2. 镜像名加入 UBI 起始地址

`include/image.mk` 增加通用变量 `DEVICE_IMG_SUFFIX`（默认空）：

```make
DEVICE_IMG_NAME = $(DEVICE_IMG_PREFIX)$(DEVICE_IMG_SUFFIX)-$(1)-$(2)
KERNEL_INITRAMFS_PREFIX = $(DEVICE_IMG_PREFIX)$(DEVICE_IMG_SUFFIX)-initramfs
```

XR1710G 设置：

```make
DEVICE_IMG_SUFFIX := _0x700000
```

生成的文件名变为：

```text
openwrt-airoha-an7581-gemtek_xr1710g-ubi_0x700000-squashfs-sysupgrade.itb
openwrt-airoha-an7581-gemtek_xr1710g-ubi_0x700000-initramfs-recovery.itb
```

其他设备 `DEVICE_IMG_SUFFIX` 为空，文件名不变。

## 关于 0x20000 布局

设备 mtd0（vendor）里的版本字符串包含：

```text
V7_3_283_2400_verify_20230428...
```

chainloader 是 0x600000 处的已签名 FIT，stock U-Boot 负责校验后加载。`0x20000` 布局需要把 bl2/fip 放到 0x0、替换整条启动链，在签名锁下不可用（除非能签发/关闭校验）。因此在这台设备上，**0x700000 + chainloader 是唯一可用布局**，W1700K 同理。
